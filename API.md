# API игры

Документ описывает внешний API, состав SQL-функций, содержимое кэша и события.
Реализации здесь нет - это черновик контракта.

## Участники

| Кто | Что делает |
|---|---|
| Пользователь | Играет, видит интерфейс |
| Клиент | Приложение в браузере: держит cookie, рисует состояние, принимает события |
| Сервер | Единственный, кто ходит в базу. Проверяет правила, ведёт SSE |
| Кэш | Память процесса: сессии, состав лобби, чей ход, подключения SSE |
| БД | PostgreSQL: источник истины, хранит всё, что переживает рестарт |

Прямого доступа клиента к базе нет. Кэш можно потерять - после перезапуска
сервера клиенты войдут заново, а состояние партий восстановится из базы.

## Ошибки

Единый формат на все ответы с ошибкой:

```json
{ "error": "не_ваш_ход", "message": "Сейчас ход другого игрока" }
```

| HTTP | Когда |
|---|---|
| 401 | Нет или просрочена сессия |
| 403 | Нет прав: не ход, не создатель, не тот игрок |
| 404 | Партия или карта не найдена |
| 409 | Состояние не позволяет: не ваш ход, партия уже идёт, место занято |
| 422 | Правило не выполнено: нечем ходить, нет места в стойле |

## Авторизация

| Метод | Путь | Возвращает |
|---|---|---|
| GET | `/api/auth/login` | `{ "url": "ссылка на страницу входа провайдера" }` |
| GET | `/api/auth/callback` | `Cookie sid` + `{ "user_id": "uuid" }` |

Провайдер входа - внешний, клиент по ссылке уходит к нему и возвращается
с кодом. Токен провайдера наружу не отдаётся, наружу только своя cookie.

Сервер берёт из токена не только `user_id`, но и роль - `user` или `admin`.
Роль кладётся в сессию в кэше. Отдельной таблицы админов в базе нет, и
не требуется: `/api/admin/*` проверяет роль в сессии и отвечает 403,
если роль не `admin`.

Все остальные эндпоинты требуют эту cookie. Cookie - `HttpOnly`, `Secure`,
`SameSite=Lax`. Сессии живут в кэше, в базе нет ни таблицы пользователей,
ни таблицы сессий.

## Партии

| Метод | Путь | Возвращает |
|---|---|---|
| GET | `/api/games` | Список открытых партий: `{ id, name, seats, occupied, needs_password }` |
| POST | `/api/games` | `{ "name": "название", "max_players": 6, "password": "необязательно" }` → `{ game_id, player_id, is_host }` |
| GET | `/api/games/{game_id}` | Полное состояние партии: игроки, их карты, стойло, сброс, чей ход, признак завершения |
| POST | `/api/games/{game_id}/join` | `{ "password": "необязательно" }` → `{ player_id, hand, is_host }` |
| POST | `/api/games/{game_id}/leave` | Пусто. До старта место освобождается, во время игры карты уходят в сброс, а игрок остаётся в партии |
| POST | `/api/games/{game_id}/start` | `{ game_state }` |
| GET | `/api/games/{game_id}/events` | Поток SSE |

`GET /api/games/{game_id}` - это же и восстановление после обрыва: клиент
просто запрашивает снимок заново.

**Про `/leave`.** Игрок не выбывает: место за ним сохраняется, карты
возвращаются в сброс, рука становится пустой. На своей очереди он просто
доберёт карты и продолжит. Выбывания в API нет.

## Ход

Все четыре эндпоинта доступны только игроку, чей сейчас ход.

| Метод | Путь | Возвращает |
|---|---|---|
| POST | `/api/games/{game_id}/draw` | `{ drawn, hand_size, game_state }` |
| POST | `/api/games/{game_id}/play` | `{ "card_id": "id карты из руки", "target_id": "id игрока для атаки, если нужно" }` → `{ applied, hand_size, game_state }` |
| POST | `/api/games/{game_id}/turn/end` | `{ game_state }` |

`game_state` в ответе - полный снимок после действия. Это проще, чем
собирать состояние из кусков: клиенту не нужно знать, что именно изменилось.

Отдельного запроса на сброс нет. Если в конце хода рука переполнена,
лишние карты уходят в сброс сами - в `sp_end_turn`. Клиент узнаёт об этом
из `game_state` и из события.

## Справочник

| Метод | Путь | Возвращает |
|---|---|---|
| GET | `/api/catalog` | Все шаблоны карт: `{ id, name, description, img_link, mechanics }`, где `mechanics` - список названий |

Полей `cost` и `stamina` в базе нет - в таблице `card_templates` только
`card_name`, `card_description` и `img_link`. Количество карт в колоде
тоже не хранится: это число строк в `cards` конкретной партии.

Читается один раз при загрузке и кэшируется клиентом.

## События SSE

Поток открывается один раз и держится. Клиент шлёт запрос на `/events`
и дальше только слушает.

```
event: game_state
data: { "game": {...} }

event: card_played
data: { "player_id": "...", "card_id": "...", "applied": [...] }

event: turn_changed
data: { "player_id": "...", "move_number": 12 }

event: player_joined
data: { "player_id": "...", "name": "..." }

event: game_over
data: { "winner_id": "...", "reason": "..." }
```

У события есть `id`. Клиент запоминает последний и при переподключении
передаёт его, чтобы получить только пропущенное.

Сервер шлёт событие всем подключённым клиентам этой партии, кроме того,
кто инициировал действие, - иначе он получит свой же ответ дважды.

Раз в 25 секунд сервер шлёт пустой комментарий-пинг, чтобы провайдер и
прокси не рвали соединение по таймауту.

## Админка

Требует роль `admin` в сессии, иначе 403. Роль приходит из токена
провайдера при входе и хранится в кэше.

Карта - это картинка, описание и набор механик. Хранится один раз в
`card_templates`. Экземпляры карт внутри партии ссылаются на шаблон,
поэтому одна карта описана один раз на всю систему.

| Метод | Путь | Возвращает |
|---|---|---|
| GET | `/api/admin/cards` | Все шаблоны: `{ id, name, description, img_link, mechanics }` |
| POST | `/api/admin/cards` | `{ "name": "...", "description": "...", "img_link": "..." }` → `{ template_id }` |
| PATCH | `/api/admin/cards/{template_id}` | Любые из `name`, `description`, `img_link` → `{ template }` |
| PUT | `/api/admin/cards/{template_id}/mechanics` | `{ "mechanic_ids": [1, 4, 9] }` → `{ mechanics }` |
| GET | `/api/admin/mechanics` | Справочник механик: `{ id, name, type }` |
| POST | `/api/admin/games/{game_id}/cards` | `{ "template_id": "...", "count": 2 }` → `{ added }` |

**Про `PUT .../mechanics`.** Список заменяется целиком, а не добавляется.
Так клиенту не нужно знать, что уже было привязано, и не нужны отдельные
`POST` и `DELETE` для привязки.

**Про создание карты.** Ссылка на картинку уникальна, повтор даёт 409.
Новую механику создать нельзя: справочник зашит в базу, пополняется
только миграцией.

**Про `/api/admin/games/{game_id}/cards`.** Добавляет в колоду партии
экземпляры карты. Работает только пока партия не началась, иначе 409.
Без этого эндпоинта колода партии наполнялась бы только при старте.

**Удаления нет.** Экземпляры карт ссылаются на шаблон с запретом удаления,
поэтому шаблон, попавший хотя бы в одну партию, удалить не получится.
Чистка - миграцией.

**Побочный эффект правки.** Экземпляры ссылаются на шаблон, а не копируют
его. Значит правка шаблона видна во всех партиях, где карта уже роздана,
включая идущие. Если это не устраивает, нужна блокировка правок, пока
есть незавершённые партии с этим шаблоном.

## Кэш

Всё в памяти процесса. Потеря не страшна.

| Ключ | Что хранит | Зачем |
|---|---|---|
| `session:{sid}` | `user_id` и роль `user` или `admin` | Не искать пользователя в базе на каждый запрос |
| `game:{id}:lobby` | Состав до старта, кто готов | Лобби живёт минуты, хранить в базе незачем |
| `game:{id}:turn` | Какой ход открыт, чей он | Читается на каждый запрос |
| `game:{id}:conns` | Открытые SSE-подключения | Раздавать события |
| `game:{id}:last_seen` | Когда клиент последний раз получил ответ | Отслеживать обрывы |

Что в кэше **не** лежит: карты, очки, кто выбыл. Это всё должно переживать
перезапуск сервера, значит только база.

Несколько экземпляров сервера: каждый держит свой кэш. События из базы
(`pg_notify`) раздаёт всем, поэтому все экземпляры разошлют событие своим
клиентам. Дубликатов не будет - событие придёт из базы один раз.

## SQL-функции

Реализации нет, только назначение и формат ответа.

### Чтение

| Функция | Что возвращает |
|---|---|
| `fn_get_game_state(id_game)` | Полный снимок партии: игроки, карты, стойло, сброс, чей ход |
| `fn_get_changes(id_game, since)` | События после указанного номера |
| `fn_list_open_games()` | Открытые партии для лобби |
| `fn_get_catalog()` | Все карты |
| `fn_get_player(id_user)` | Игрок по идентификатору пользователя |
| `fn_check_victory(id_game)` | Победитель и причина, либо пусто |
| `fn_get_health()` | Жива ли база |

### Запись

| Функция | Что делает | Ошибки при нарушении правил |
|---|---|---|
| `sp_create_game(id_user, name, max_players, password)` | Создаёт партию, выдаёт место и карты | - |
| `sp_join_game(id_user, id_game, password)` | Пускает в партию, выдаёт карты | пароль, нет места, уже началась |
| `sp_leave_game(id_player, id_game)` | Убирает игрока из лобби или сбрасывает его руку в игре | - |
| `sp_start_game(id_game)` | Проверяет готовность, раздаёт, открывает первый ход | не все готовы, мало карт |
| `sp_draw_cards(id_game)` | Берёт карты из колоды в руку | ход не его, рука полна |
| `sp_play_card(id_game, id_card, target_id)` | Проверяет и применяет механику карты | не его ход, карты нет в руке, нет места в стойле |
| `sp_discard_cards(id_game, ids)` | Возвращает карты из руки в сброс. Вызывается только из `sp_end_turn` и `sp_leave_game`, отдельного эндпоинта нет | рука не переполнена |
| `sp_end_turn(id_game)` | Закрывает ход, сбрасывает лишние карты, увеличивает счётчик ходов игрока | не его ход, нельзя завершить |
| `sp_begin_turn(id_game)` | Открывает ход следующему по счётчику игроку | ход уже открыт |
| `sp_skip_turn(id_game)` | Пропускает ход отсутствующего игрока | ход открыт у игрока на связи |

### Админка

| Функция | Что делает | Ошибки при нарушении правил |
|---|---|---|
| `fn_list_card_templates()` | Все шаблоны вместе с механиками | - |
| `fn_get_card_template(id)` | Один шаблон с механиками | шаблона нет |
| `fn_list_mechanics()` | Справочник механик | - |
| `sp_create_card_template(name, description, img_link)` | Создаёт шаблон карты | такая картинка уже есть |
| `sp_update_card_template(id, name, description, img_link)` | Прав��т шаблон | шаблона нет, такая картинка уже есть |
| `sp_set_card_mechanics(id_template, mechanic_ids)` | Заменяет набор механик карты целиком | неизвестная механика |
| `sp_add_cards_to_game(id_game, id_template, count)` | Кладёт экземпляры карты в колоду партии | партия уже началась, неизвестный шаблон |

Роль проверяет сервер по сессии. В базе проверок прав нет и не нужно:
прав на запись в библиотеку карт в схеме не предусмотрено.

### События

| Функция | Что делает |
|---|---|
| `fn_notify(...)` | Отправляет событие в канал. Вызывается внутри каждой записи |

## Правила, которые живут в базе

- Все проверки - внутри функций записи. Клиент может прислать что угодно,
  решение принимает база.
- Запись всегда в транзакции и всегда с блокировкой строки партии:
  два игрока не могут одновременно сыграть карту.
- Порядок вызовов на ход: `sp_play_card` или `sp_draw_cards`, затем
  `sp_end_turn`, затем `sp_begin_turn` для следующего игрока.
